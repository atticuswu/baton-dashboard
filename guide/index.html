01

以 Git 為核心的做法

先給你一個錨點，後面的細節才掛得上去。

所有專案的進度檔都放在同一個 Git 倉庫裡。 每台機器 clone 同一份，開工先拉，收工就推。

這套做法只有四樣東西

中樞倉庫hub repo
一個私有的 GitHub 倉庫，所有專案的進度檔都住在裡面。
三台機器都 clone 到同一個路徑，例如 ~/Project/Baton/。它是唯一的真相，儀表板只是它的視圖。
流水帳progress.md
每次 session 做完，往後面加一段。只追加，不改舊的。
標日期、機器、做了什麼、卡在哪。因為只往後加，兩台機器同時寫也幾乎不會撞。
交接單handoff.md
目前做到哪、下一步是什麼。整份改寫，維持 40 行以內。
開頭一小段結構化欄位，儀表板就讀這裡。下一個 session 不管在哪台機器，先讀它就能接手。
規則CLAUDE.md
告訴 Claude 怎麼工作的說明書。很少改。
分三層：機器層、中樞層、專案層。Claude 開 session 時會自動把這三層都讀進去。

02

每次完成都會有接力的文件

先有個粗略的畫面，下一段再換成正確的結構。

整套做法就像公司裡的交接本，放在一個大家都拿得到的共用櫃子。
共用櫃子，誰都能打開 = GitHub 上的中樞倉庫
每個專案一本交接本，第一頁寫「現在做到哪、下一步」 = handoff.md 交接單
交接本後面的日誌頁，每天往後寫一條 = progress.md 流水帳
貼在櫃子門上的工作守則 = CLAUDE.md 規則
上班先翻交接本，下班寫完放回櫃子 = 開 session 先 pull，收工自動 push
類比在哪裡不準：紙本只有一份，兩個人同時拿走就打架，而且舊的寫法擦掉就沒了。 Git 則是每台機器各有一份完整副本，每一版都留著。兩邊同時改到同一行時，它會明確告訴你撞到了，不會默默蓋掉。
03

GitHub 中樞倉庫

誰連到誰、檔案放哪、哪個檔案誰來寫。

三台機器都只跟 GitHub 說話，彼此不直接連線

實線是「拉下來再推上去」，雙向都走。虛線表示雲端 session 走同一套規則，只是它沒有本機硬碟，一切從 GitHub 拿。 紅色那一格是整套系統唯一的真相。

三個檔案各管一件事，不要混

檔案 它是什麼 誰在什麼時候寫 誰來讀
CLAUDE.md 規則。怎麼工作、資料夾怎麼放、檔案格式長怎樣。 你，偶爾改一次。狀態不要寫進來。 Claude 每次開 session 自動讀。
handoff.md 現況。做到哪、下一步、要小心什麼。40 行以內。 Claude 每輪做完整份改寫。你也可以在儀表板改。 下一個 session 的 Claude，還有儀表板。
progress.md 流水帳。每段標日期、機器、做了什麼。 Claude 每輪做完往後追加一段，不動舊的。 你回頭查歷史時，還有儀表板的「記錄簿」頁。

CLAUDE.md 分三層，開 session 時會一層一層疊上去

機器層~/.claude/CLAUDE.md 每台機器各寫各的。寫「本機代號 mac-mini」、語言偏好、你的個人習慣。有了它，流水帳才標得出是哪台機器寫的。旁邊的 ~/.claude/settings.json 放 hooks，不管在哪個資料夾開 session 都生效。 每台不同
中樞層~/Project/Baton/CLAUDE.md 工作流程的四個固定步驟：讀交接單、做事、追加流水帳、改寫交接單後推上去。也寫資料夾規則與檔案格式。 全部共用
專案層~/Project/Baton/content-studio/CLAUDE.md 只寫這個專案的背景、技術、禁忌。再用一行 @handoff.md 把交接單匯進來，Claude 一開就讀到現況。 每專案一份

Claude Code 會從你所在的資料夾一路往上找 CLAUDE.md 全部載入，所以在專案資料夾開 session，三層自然都在。

05

最容易想錯的四件事

這四個是討論過程中真的冒出來過的念頭。

你可能以為
「直接用 iCloud 資料夾，就不用搞 git 了。」
其實
iCloud 只解決「兩台 Mac 看到同一份檔案」。Groq bot 掛不到 iCloud，儀表板讀不到 iCloud，雲端 session 也看不到。而且 iCloud 遇到衝突不會告訴你，只會默默多出一個「progress 2.md」。iCloud 適合放影片、圖片這類大檔，不適合當進度的真相。
你可能以為
「Stop hook 是整個 session 結束時才跑一次。」
其實
Claude 每回答完一輪就觸發一次。一個 session 聊二十輪，它就跑二十次。所以 sync.sh 第一件事是檢查有沒有改動，沒有就靜靜結束，不會製造二十個空 commit。
你可能以為
「把進度寫進 CLAUDE.md 最保險，反正每次都會讀。」
其實
CLAUDE.md 放的是規則，很少改。狀態要放 handoff.md，用 @handoff.md 那一行匯進來，效果一樣是每次都讀到。把狀態混進規則檔，是這類系統最常見的失控來源，規則會越寫越長、越來越沒人敢動。
你可能以為
「要在每台電腦手動建一樣的資料夾結構。」
其實
git clone 下來，倉庫裡的結構就自動一模一樣。你唯一要自己決定並保持一致的，只有倉庫放在哪個路徑，建議三台都放 ~/Project/Baton/。刻意不一樣的只有三樣：機器層的 CLAUDE.md、被忽略的大檔資料夾、大型程式碼倉庫的位置。
06

什麼時候會卡住

知道邊界比知道機制重要，不然會套到不該套的地方。

06.1
同一個專案，兩台機器同時改
兩邊都改寫 handoff.md 再推，後推的那台會在 pull 時撞到衝突，流程停住、不會推上去。解法是交接單裡的 owner 欄位：儀表板顯示現在誰在做，同一專案同時只在一台機器上動。
06.2
Groq bot 主機只放行 HTTPS，也沒有路連回 Mac
那台是 Grok Bot app 配給 bot 的雲端 Linux，出口代理擋掉所有 SSH，部署金鑰用不了，GitHub 得走 HTTPS 加一個只給 Baton 的 fine-grained token（存在 bot 的加密欄位）。它也連不到 Mac，倉庫只能從 GitHub clone，不能從 mini 複製。bot 若不經 claude CLI 直接改檔，要自己做「開工 pull、收工 sync.sh」。
06.3
影片、圖片、大型匯出檔
這些不該進 git，倉庫會越來越肥、clone 越來越慢。放 iCloud 或 Drive，文件裡放路徑或連結就好。
06.4
大型程式碼專案
有自己的建置流程、很多檔案的專案，另開倉庫。中樞只放它的三個控制檔，用 @ 匯入那一行把兩邊接起來，在哪邊開 session 都讀得到交接單。
06.5
雲端的 Claude session
像現在這個 session 沒有你的硬碟，只看得到有加進環境的 GitHub 倉庫。要讓它參與，就把中樞倉庫加進雲端環境，它會走同一套 pull 與 push。
06.6
現成的開源工具只是零件
GitHub 上有人做了 git 同步的交接檔、也有人做了 markdown 看板，但沒有人把「跨機器、網頁可改、三種 AI 都能讀」合起來。可以借零件，儀表板那薄薄一層還是要自己寫。

要動手時看這裡

主線到上一段就完整了。以下是真的要建的時候才需要的格式、腳本與順序。

handoff.md 交接單的格式格式

開頭那一段三條橫線夾起來的欄位，就是儀表板的資料來源。下面三段用人話寫，40 行以內。

area: 內容事業
status: active          # active | paused | someday | done
owner: mac-mini         # 目前由哪台機器負責

updated: 2026-11-05T14:20+08:00

## 陷阱與注意事項
progress.md 流水帳每一段的格式格式

只往後追加。標題行寫日期時間、機器代號、用的是哪個工具。機器代號來自機器層的 CLAUDE.md。上個月以前的段落由 sync.sh 自動搬到 progress/YYYY-MM.md（roll-progress.py，兩台同時跑結果一樣），不要手動搬。儀表板依日收合，只展開最新一天。

hooks 設定，每台機器放一次腳本

放在每台機器的 ~/.claude/settings.json，三台內容一樣。這樣不管在哪個資料夾開 session，連獨立的程式碼倉庫也一樣，都會先拉中樞、做完推中樞。專案層的 .claude/settings.json 只在啟動的那個資料夾生效，不會往上找，所以不要把 hooks 放在中樞根目錄。

{
  "hooks": {
    "SessionStart": [{"hooks": [{"type": "command",
      "command": "git -C \"$HOME/Project/Baton\" pull --rebase --autostash -q || true"}]}],
    "Stop": [{"hooks": [{"type": "command",
      "command": "\"$HOME/Project/Baton/scripts/sync.sh\""}]}]
  }
}
sync.sh 本體，只有六行腳本

固定對中樞倉庫動作，不管 session 開在哪。第三行是安全閥：沒有改動就直接結束。第五行先 pull 再 push，撞到衝突時 pull 會失敗，整行就停在那裡，不會推。

#!/usr/bin/env bash
cd "$HOME/Project/Baton" || exit 0
git add -A
git diff --cached --quiet && exit 0
git commit -qm "progress: $(hostname -s) $(date +%Y-%m-%dT%H:%M)"
git pull --rebase --autostash -q && git push -q
儀表板現在長這樣儀表板
  1. 入口頁 baton.atticus.tw。一個網域放多個儀表板，dashboards.js 是登錄表；整個 dashboard/ 資料夾由 GitHub Actions 推到公開倉庫 baton-dashboard，用它的 GitHub Pages 發布。
  2. 專案儀表板 /projects/。版型照 Things：今天、即將、隨時、某天、記錄簿、全部專案。專案頁有「完成路徑」圖：下一步的勾選框依序排成一條路，終點是 goal，### 子標題變成階段。現況條列、陷阱收合、流水帳依日收合。
  3. 寫回兩條路。勾選框：瀏覽器裡的 fine-grained token（只給 Baton 的 Contents 與 Issues 讀寫）直接改 handoff.md 那一行，一個 commit。輸入列：開一張 claude 標籤的 Issue，claude-task.yml 用 Claude Code 無頭模式改該專案的檔案、commit、回覆並關閉 Issue。

公開網址沒有存取控制，任何專案的 handoff.md 全文與最近 80 段流水帳都看得到，帳號、金額、私人資訊不要寫。

現有專案怎麼搬進來遷移
  1. 新專案用 /new-project 指令（或 scripts/new-project.sh），它會建資料夾、三個控制檔、登記 projects.yaml。完整啟動流程在 baton/docs/new-project-flow.md。
  2. 既有專案：在它現在的 session 裡請 Claude「把目前狀態依新格式寫成 handoff.md，把既有 progress.md 整理成新格式」，再把 Claude App 的選取資料夾換成 ~/Project/Baton/<專案>。
  3. 大型程式碼專案留在自己的倉庫，中樞只放三個控制檔，那邊的 CLAUDE.md 加一行 @~/Project/Baton/<專案>/handoff.md。
三台機器怎麼接上 GitHub機器
  1. 每台都一樣的部分：clone 到 ~/Project/Baton，跑 scripts/install.sh <本機代號>。它把 hooks 合進 ~/.claude/settings.json、在 ~/.claude/CLAUDE.md 加本機區塊、連結 /wrap 與 /new-project、把代號寫進 ~/.config/baton/machine。
  2. Mac mini：HTTPS，靠 gh 當 credential helper。
  3. MacBook Air：專用 SSH 金鑰 ~/.ssh/id_ed25519_baton 加為倉庫的可寫入部署金鑰，ssh 別名 github-baton，remote 是 git@github-baton:atticuswu/Baton.git。
  4. Groq bot 主機：HTTPS，fine-grained token 存進 credential helper；bot 收到指示後自己 clone、跑 install.sh groq-bot。
  5. 驗 hooks：Claude App 裡沒有 /hooks，用無頭 CLI：cd ~/Project/Baton/<專案> 後跑 claude -p "只回覆 OK" --output-format stream-json --verbose --include-hook-events，看 SessionStart 與 Stop 的 hook_started／hook_response。在 Mac 上要在本機終端機跑，SSH 進去讀不到鑰匙圈裡的登入。
