Baton 接力棒 · 單一專案的目標流程 · 2026-11-07

一個專案怎麼在三台機器間接力而不掉棒

Baton 裡的每個專案都是一個資料夾、三個控制檔。開 session 自動拉最新進度，收工自動推回去，儀表板讀同一份檔案， 在儀表板上勾選或下指示也會寫回同一份檔案。這一頁用一個專案走完整圈，告訴你棒子在哪、誰拿著、怎麼交。

01

一句話

這是什麼、不這樣做會怎樣

一個專案的「現況」只存在一個地方：GitHub 上 main 分支的 handoff.md。 每台機器開 session 先拉它、收工先推它，儀表板只是把它投影出來。棒子永遠只有一根，誰拿著寫在檔案裡的 owner 欄。

交接單handoff.md
專案此刻的狀態：做到哪、下一步、要小心什麼。整份覆寫，40 行以內。
開頭一段 front matter 給儀表板讀：owner 是誰持棒、next 是最該做的一件事、due 與 updated。「下一步」的勾選框就是儀表板上的任務。
流水帳progress.md
每做完一輪就在末尾追加一段，從不改舊段落。
段落標題寫日期、機器代號、工具。兩台同時追加也不會衝突，因為 git 設了 merge=union，兩邊的段落都留下。
接力棒owner 欄
handoff.md 裡寫著目前哪台機器負責；接手前看它，接手時改成自己。
handoff.md 沒有合併保護，兩台同時改寫會停住等人解。所以靠這個欄位約定：同一時間只在一台機器上動同一個專案。
不這樣做會怎樣：每台機器各有一份「我記得做到哪」，換機器就要從頭講一次；儀表板上看到的也是舊的。Baton 把這三件事收成同一份檔案，由 git 負責搬運。
02

類比

名字就叫接力棒，拿接力賽來對照最直接
一個專案的進度，像接力賽裡的那根棒子
棒子本身↔handoff.md：現況、下一步、陷阱
正在跑的那位選手↔owner 欄寫的那台機器
交棒區：交之前要確認對方伸手了↔收工 /wrap 改寫交接單、sync.sh 推上 GitHub
接棒的選手起跑↔另一台開 session，SessionStart hook 自動 pull
每一棒的分段計時↔progress.md 只追加的段落
場邊的計分板↔baton.atticus.tw 儀表板
類比在哪裡失準：接力賽的計分板只能看，Baton 的儀表板可以直接在棒子上寫字：勾一下就改 handoff.md，打一句話就有 Claude 幫你改。 另外接力賽交棒是面對面，Baton 是透過 GitHub 轉交，接棒的機器要等到下次開 session 才會拿到。
03

核心模型

五道泳道：持棒的機器、GitHub main、GitHub Actions、儀表板、接棒的機器。點任一格看它在做什麼、怎麼驗

藍線是棒子走的路：推上 main、再被另一台拉下來。虛線是系統自己接的：Claude 改完檔觸發重建，接棒的機器接著成為持棒者。

05

常見誤解

你以為是這樣，其實是那樣
常見的理解
儀表板是另一份資料，勾了要再同步回專案。
實際上
儀表板只是 main 上 handoff.md 的投影。勾選就是改那個檔案並 commit，沒有第二份資料要對。
常見的理解
程式碼也要搬進 Baton 才算納管。
實際上
大型程式碼留在自己的倉庫，Baton 只放三個控制檔。程式碼倉庫的 CLAUDE.md 加一行匯入交接單，開 session 一樣讀得到。
常見的理解
兩台機器可以同時做同一個專案，git 會幫忙合併。
實際上
progress.md 可以兩邊同時追加；handoff.md 不行，撞到就停住等人解。所以才有 owner 欄：同一時間只有一台持棒。
常見的理解
輸入列送出的指示要等某台機器醒著才會處理。
實際上
處理的是 GitHub Actions 裡的 Claude，不靠任何一台機器。兩三分鐘內 Issue 底下會有回覆與 commit 連結。
06

邊界

什麼時候不適用、什麼時候會壞
!
儀表板是公開的
任何專案的 handoff.md 全文與 progress.md 最近 8 段都會出現在 baton.atticus.tw。帳號、金額、私人資訊不要寫進這兩個檔。要保護得換託管。
!
Stop hook 對這台機器上所有 session 都會觸發
別的 session 一結束回合，sync.sh 就把 Baton 工作區當下的狀態全部 commit 推走。在 Baton 裡做半途的改動要一氣呵成。
!
Actions 裡的 Claude 看不到任何硬碟
它只有這個倉庫，只准動該專案資料夾。要它建倉庫、裝 hooks、碰本機檔案做不到，那是「機器互連」待辦要解的事。
!
寫回的 commit 直接進 main
某台機器若有還沒 commit 的 handoff.md 改動，下次 SessionStart 的 pull --rebase 可能撞到。撞到會停下來，不會自動解。
!
handoff.md 40 行、progress 只追加
交接單超過 40 行就不是交接單；舊段落被改掉就不是流水帳。兩條都是人為約定，工具不會擋。
!
接棒要等下次開 session
Baton 不即時推送。另一台正在進行中的 session 不會自己拿到新的 handoff，它開頭讀到什麼就是什麼。
07

速查

檔案、指令、憑證放哪。主線讀完就夠用，這裡是要動手時翻的
每個專案的三個控制檔，各自的規則檔案
檔案性質規則
CLAUDE.md規則第一行 @handoff.md 匯入交接單；只放規則不放狀態，少改
handoff.md現況整份覆寫，40 行以內；front matter 給儀表板讀；「下一步」勾選框就是儀表板任務
progress.md流水帳只追加；段落標題「日期 時間 · 機器代號 · 工具」；merge=union 保護雙邊追加
指令與腳本指令
指令做什麼
/wrap收工：追加 progress、改寫 handoff、跑 sync.sh
/new-project slug 中文名 分類開新專案：建資料夾、登記 projects.yaml、陪你填 CLAUDE.md 與第一版 handoff
scripts/install.sh 機器代號一台機器裝一次：hooks 合併進使用者層設定、連結指令、寫本機代號
scripts/sync.shStop hook 呼叫：有改動才 commit、pull --rebase、push；互斥鎖防兩份同時跑
scripts/build-dashboard.py掃所有 handoff 與 progress 產出 dashboard/projects/data.js

完整的新專案啟動流程與搬既有專案的做法在倉庫的 baton/docs/new-project-flow.md。

憑證放哪，各管什麼憑證
憑證放哪給誰用
GitHub fine-grained token（Baton 的 Contents 與 Issues 讀寫）瀏覽器 localStorage儀表板的勾選寫回與開 Issue
CLAUDE_CODE_OAUTH_TOKENBaton 的 Actions secretclaude-task.yml 裡的 Claude Code
DASHBOARD_DEPLOY_KEYBaton 的 Actions secret，公鑰在 baton-dashboard 的 Deploy keysdashboard.yml 推公開倉庫
Cloudflare tokenMac mini 的 ~/.config/cloudflare/token改 atticus.tw 的 DNS（baton 這筆 CNAME）

值一律不進倉庫、不進儀表板。
